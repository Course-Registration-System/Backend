# 시드 데이터 안내

개발·테스트·시연 모두 이 데이터를 쓴다. `tools/seed/build_seed.py` 가 만든다(직접 고치지 않는다). 모든 계정의 비밀번호는 `test1234!` 다.

## 시연 흐름

2026-2 성적을 입력·확정하면 그 성적으로 2027-1 최대학점이 정해지고, 그 학점으로 수강신청이 막히거나 허용된다.

| 순서 | 시각 | 누가 | 무엇을 | 데이터 |
| --- | --- | --- | --- | --- |
| ① 성적 입력 | T0 2026-12-21 10:00 | 교수 100002 | 182번 데이터리터러시(1030018-1)에서 20260001 원점수 입력(항목 91점씩) 후 제출 | 저장하면 12명 석차로 다시 계산: 20260001 A 구역 → 최종점수 91, A-. A 3명 + 1 = 한도 4명 |
| ② 성적 확정 | TC 2026-12-28 10:00 | 관리자 90001 | 시계를 TC로 옮긴 뒤 미입력 강의 158번 소프트웨어공학(1010016-1) 확인, 2026-2 제출 강의 확정. 확정은 성적 입력 기간(12-23 18:00)이 끝난 뒤에만 되므로 T0 에서는 막힌다 | 기본 시드 |
| ③ 학기 마감 | (TC → T1) | 관리자 90001 | 겨울학기 성적 확정, 진급·졸업·복학, 2027-1 최대학점 산정 | `s1_grade_close` 후 앱 기능으로 다시 산정 |
| ④ 시계 넘김 | T1 2027-02-11 10:05 | 시연 API | 다른 학생들의 장바구니와 4·3학년 신청을 채움 | `s2_enroll_day` |
| ⑤ 수강신청 | T1 | 학생 20260001 | 장바구니 18학점 + 203번 3학점 = 21학점 신청 성공. 190번은 정원 마감으로 차단 | s2 이후 |
| ⑥ 차단 사례 | T1 | 학생 여럿 | 아래 모듈 B 표의 T1 사례 | s2 이후 |
| ⑦ 데이터 제어 | T1 | root·app·readonly | `demo/` SQL | s2 이후 |

①에서 89점 이하(B+)를 넣으면 평점이 4.0 아래가 되어 ③의 최대학점이 19가 되고, ⑤에서 21학점 신청이 막힌다. `s1_grade_close` 는 최대학점을 미리 계산해 둔 값(22)으로 넣으므로 이 대비를 보이려면 s1 을 넣은 뒤 앱으로 2027-1 최대학점을 다시 산정한다(다시 산정하면 그 학기 값을 지우고 새로 계산한다). 2027-1 산정은 겨울학기 성적까지 확정돼야 하므로 s1 없이 T0 에서 바로 실행하면 `GRADES_NOT_CONFIRMED` 로 막힌다.

## 시점과 오버레이

| 시점 | 시각 | 열린 기간 | 적용할 오버레이 |
| --- | --- | --- | --- |
| T0 | 2026-12-21 10:00 | 2026-2 성적 입력, 2026 겨울 정정 | 없음(기본 시드) |
| TC | 2026-12-28 10:00 | 없음. 2026-2 성적 입력이 끝나 확정 가능 | 없음(기본 시드) |
| T1 | 2027-02-11 10:05 | 2027-1 2학년 수강신청 | `s1_grade_close`, `s2_enroll_day` |
| T2 | 2027-03-04 11:00 | 2027-1 정정(전 학년) | `s1_grade_close`, `s2_enroll_day`, `s3_adjust` |

오버레이는 `src/main/resources/db/scenario/` 에 있고, 앞 단계부터 순서대로 한 번씩 적용한다. 되돌리려면 `docker compose down -v` 후 다시 올린다.

### 시점 바꾸기

- **시연·로컬(권장)**: 시연 API 로 오버레이를 넣고 시계를 옮긴다. 프로필을 지정하지 않으면 demo 라 바로 쓸 수 있다. 같은 오버레이를 두 번 넣으면 409 로 거절하고 데이터는 그대로다.

  ```bash
  curl -X PUT 'localhost:8080/api/dev/clock?at=2026-12-28T10:00:00'   # ② 성적 확정
  curl -X POST localhost:8080/api/dev/scenarios/s1_grade_close
  curl -X POST localhost:8080/api/dev/scenarios/s2_enroll_day
  curl -X PUT 'localhost:8080/api/dev/clock?at=2027-02-11T10:05:00'
  curl localhost:8080/api/dev/clock
  ```

- **서버 시작 시각**: `.env` 의 `CLOCK_FIXED_AT` (기본 T0). 비우면 실제 시각.
- **테스트**: `@TestPropertySource(properties = "crs.clock.fixed-at=" + SeedTime.T1)` 로 시각을 고르고, `SeedTime.atT1(dataSource)` 로 오버레이를 테스트 트랜잭션 안에서 적용한다. 사례는 `SeedFixtures` 상수로 가리킨다.
